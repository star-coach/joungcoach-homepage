# JOUNG COACH Homepage v4 — Firebase CMS

이 버전부터는 글 1개를 추가할 때 홈페이지 전체 파일을 다시 업로드하지 않습니다.
관리자 페이지(admin.html)에서 저장하면 Firebase Realtime Database에 그 항목만 저장되고, 공개 홈페이지가 실시간으로 읽어 표시합니다.

## 최초 1회 설정

1. Firebase Console > Authentication > Sign-in method > Email/Password 활성화
2. Authentication > Users > 사용자 추가에서 본인 관리자 이메일/비밀번호 1개 생성
3. Realtime Database > Rules에 `database.rules.json` 내용을 반영
4. Storage > Rules에 `storage.rules` 내용을 반영
5. GitHub의 기존 홈페이지 파일을 이 v4 파일로 교체하고 Commit
6. Netlify가 GitHub와 연결되어 있으면 자동 배포됨
7. 배포 주소 뒤에 `/admin.html`로 접속하여 로그인
8. 첫 로그인 후 대시보드에서 `초기 콘텐츠 Firebase에 넣기`를 한 번 클릭

## 이후 운영

- 새 글: 관리자 > 글과 기록 > + 새 글 > 저장
- 새 활동: 관리자 > 활동 > + 새 활동 > 저장
- 연구: 관리자 > 연구에서 추가/수정/삭제
- 프로필: 관리자 > 프로필·철학에서 수정 및 사진 업로드
- 연락처: 관리자 > 연락처

GitHub는 홈페이지 코드가 바뀔 때만 수정합니다. 콘텐츠 추가/수정은 Firebase에서 처리됩니다.

## 중요

- 이 프로젝트는 Firebase `stocky-8fbdc`를 사용하도록 설정되어 있습니다.
- 모든 홈페이지 데이터는 `homepage/` 경로 아래에만 저장되어 기존 앱 데이터와 분리됩니다.
- Firebase Storage가 요금제/버킷 정책 때문에 업로드를 허용하지 않는 경우, 글 텍스트 저장은 정상 동작하고 이미지 업로드만 실패할 수 있습니다.


## 관리자 로그인과 이미지 등록

### 로그인 유지

- 관리자 인증은 Firebase Authentication의 이메일/비밀번호 방식이며 주소는 `/admin.html`입니다.
- 브라우저에서 Firebase Auth의 기본 로그인 지속성은 로컬 저장 방식입니다. 로그인 후 같은 브라우저·기기에서는 다음 방문에도 로그인 상태가 남으며, 로그아웃하거나 브라우저 사이트 데이터를 지우면 다시 인증해야 합니다. Firebase 인증은 도메인별로 분리되므로 운영자 브라우저와 자동화 브라우저의 로그인 상태는 서로 공유되지 않습니다.
- 계정 비밀번호를 코드, GitHub, Notion에 기록하지 않습니다. 개인 휴대폰에서 자동 입력을 원하면 Chrome의 Google 비밀번호 관리자에 `joungcoach.com` 로그인을 직접 저장하고 기기 생체인증/화면잠금을 사용합니다.

### 사진 올리기

1. 관리자에서 `교육·교재`를 열고 글을 새로 만들거나 수정합니다.
2. 대표 사진은 `대표 이미지 > Choose File`, 추가 사진(예: PPT 표지)은 `추가 사진 갤러리 > Choose Files`에서 선택합니다. 캡션을 입력한 뒤 `저장`을 누릅니다.
3. 저장 전 미리보기와 파일 크기가 0보다 큰지 확인합니다. 파일이 비어 있으면 저장을 중단하고 원본을 다시 선택합니다.
4. 성공 안내를 확인한 뒤 공개 홈페이지의 글 상세를 열어 대표 사진과 갤러리 이미지가 실제 표시되는지 확인합니다.

### 자동화 시 유의사항

- 글·사진은 Firebase CMS에 직접 저장하므로 일반 게시물 등록에 GitHub 코드 변경은 필요하지 않습니다.
- 브라우저 자동화는 파일 선택창에 브라우저가 접근할 수 있는 공유 경로의 원본 파일을 넘깁니다. 저장 버튼을 눌렀다는 사실만으로 완료로 간주하지 않고, 선택된 파일 크기와 공개 상세 이미지의 실제 로딩을 확인합니다.
- 공개 게시 전에 글의 날짜·제목·본문·공개 체크를 검토합니다. 사용자 로그인 비밀정보는 자동화 메모리에 저장하지 않습니다.
